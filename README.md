### Description
The goal of this project is to create a private infrastructure for web applications, including a NGINX web server, a MariaDB database and a WordPress CMS website. The project is designed to be completed in a virtual machine environment, and it requires the use of Docker and Docker Compose to set up the necessary containers for the web server, database, and CMS.
The project also includes a set of instructions for configuring the containers and setting up the necessary environment variables to ensure that the web server, database, and CMS are properly connected and functioning together.
There're also detailed instructions for the user to follow in order to set up the project, including the necessary commands to run the Docker containers, configure the environment variables and access the web application through the web browser under a determined domain name.
The project also contains a file with instructions for the system administrator to configure the necessary settings and permissions for the web server, database and CMS, as well as a set of instructions for troubleshooting common issues that may arise during the setup process.

#### What's a virtual machine?
A virtual machine (VM) is a software-based emulation of a physical computer. It allows you to run multiple operating systems inside the host operating system, each with its own virtual hardware and software environment. This allows you to test and develop applications in a controlled environment without affecting the host system.

#### What's Docker and what's the difference between Docker and a virtual machine?
Docker is a platform that allows you to create, deploy, and run applications in containers. Containers are lightweight, portable, and self-contained environments that can run on any system that supports Docker. Unlike virtual machines, which require a full operating system to run, containers share the host operating system's kernel and resources, making them more efficient and faster to start up. Docker allows you to package your application and its dependencies into a single container, which can be easily deployed and run on any system that supports Docker. This makes it easier to manage and scale applications, as well as to ensure that they run consistently across different environments.

#### What's the difference between a "secrets" folder and a ".env" file?
A "secrets" folder is a directory used to store sensitive information such as API keys, passwords, and other confidential data. This folder is typically excluded from version control systems to prevent unauthorized access to the sensitive information. A ".env" file, on the other hand, is a file that contains environment variables that are used to configure the application. The ".env" file is usually included in version control systems, but it should only contain non-sensitive information for security reasons. 

#### Docker Network vs Host Network
Docker Network is a virtual network that allows containers to communicate with each other and with the host system. It provides isolation and security for the containers, allowing them to run in their own network namespace.
Host Network, on the other hand, allows containers to share the host system's network stack.

#### Docker Volumes vs Bind Mounts
Docker Volumes are a way to persist data generated by and used by Docker containers. They are managed by Docker and can be easily created, backed up, and restored. Volumes are stored in a specific location on the host system and can be shared between containers. Bind Mounts, on the other hand, allow you to mount a specific file or directory from the host system into a container. Usually bind mounts are used for development purposes, as they allow you to make changes to the files on the host system and have those changes reflected in the container in real-time.

### Instructions
1. Clone the repository to your local machine.
2. Navigate to the project directory and run the following command to build the Docker containers:


   ```bash
   make build
   ```

This will start the containers for the NGINX web server, MariaDB database, and WordPress CMS website. The containers will be configured to work together and will be accessible through the specified domain name. It will also configure the necessary environment variables to ensure that the web server, database and CMS are properly connected and functioning together.

To run the containers properly, you will need to add a folder named "secrets" in the root of the project directory, and inside that folder you will need to create several files with the necessary credentials and configuration for accessing the database and the CMS. The files that need to be created inside the "secrets" folder are:
- `db_root_password` - contains the password for the root user of the MariaDB database.
- `db_health_user` - contains the username for the health check user of the MariaDB database. this user is needed to check 	the health of the database and ensure that it is running properly.
- `db_health_password` - contains the password for the health check user of the MariaDB database.
- `wp_db_name` - contains the name of the WordPress database.
- `wp_db_password` - contains the password for the WordPress database user.
- `wp_db_user` - contains the username for the WordPress database user.
for the CMS, it will be necessary to create the following files:
- `wp_user` - contains the username for the WordPress user.
- `wp_user_password` - contains the password for the WordPress user.
- `wp_user_email` - contains the email for the WordPress user.
- `wp_admin_password` - contains the password for the WordPress admin user.
- `wp_admin_email` - contains the email for the WordPress admin user.

3. Once the containers are up and running, you can access the web application by navigating to the specified domain name in your web browser.

4. other commands that can be used to manage the containers include:
   - `make up` - to start the containers
   - `make down` - to stop the containers
   - `make logs` - to view the logs of the containers
   - `make status` - to check the status of the containers
   - `make fclean` - to remove the containers and their associated data
   - `make restart` - to restart the containers
   - `make config` - to view the configuration of the containers
